# Internationalization

Three separate datasets, all in `src/data/`, plus sort labels in
`domain/manifest.js`. **19 languages**: es, en, de, fr, it, pt, nl, sv, no, da,
fi, pl, ja, ko, ar, hi, te, ml, kn.

## The language set is derived, not declared

`getSupportedLanguages()` extracts the language codes from the `GENRES`
translations themselves, sorts Spanish first, then English, then alphabetically
by display name, and attaches `LANGUAGE_NAMES[code]` for display.

**The UI-strings language set is deliberately identical to the catalog language
set** — the page's language picker offers exactly the languages the addon can
actually serve catalogs in. `test/uiStrings.test.js` enforces the equality in
**both** directions, so adding a genre language without UI strings (or the
reverse) fails the suite.

## Datasets

| Dataset             | Where                        | What                                                          |
| ------------------- | ---------------------------- | -------------------------------------------------------------- |
| `GENRES`            | `data/catalogMeta.js`        | ~18 genres × 19 languages, keyed by JustWatch `shortName`      |
| `SORT_LABELS_I18N`  | `domain/manifest.js`         | Popular / Trending / New per language, for catalog headers      |
| `UI_STRINGS`        | `data/uiStrings.js`          | ~37 keys × 19 languages for `/configure`                        |
| country names       | `data/catalogMeta.js` (ICU)  | derived at runtime, see below                                   |

All of them fall back to English for an unknown language and handle BCP-47 tags
by taking the primary subtag (`pt-BR` → `pt`).

`getGenreNames(lang)` / `getGenreCode(name, lang)` round-trip; `translations.test.js`
checks stability, uniqueness within a language, and no empty strings.

## `/configure` translations (2026-08-26)

Replaced a floating "Traducir con Google" button (which just opened
`translate.google.com`) with a **first-party** layer — the page no longer
depends on any external translator.

- `data/uiStrings.js`: `UI_STRINGS[lang][key]`. **Spanish is the source of
  truth** (it's what `configure.html` ships hardcoded); English is merged under
  every language by `getUiStrings(lang)` as the per-key fallback. Also exports
  `RTL_UI_LANGUAGES = ["ar"]` and `DEFAULT_UI_LANGUAGE = "es"`.
- `GET /api/ui-strings?lang=xx` → `{ lang, rtl, strings }`, 400 on a malformed
  code, `no-store`.
- Client side: `data-i18n`, `data-i18n-placeholder`, `data-i18n-title`
  attributes plus a `t(key, vars)` helper for JS-generated text. See
  [configure-ui.md](configure-ui.md) for the FAB and the `data-i18n` removal
  gotcha.
- `loadMore` is the one string with a `{n}` placeholder — a test asserts every
  language keeps it.

## Country names — ICU, not a table

`localizeCountries(lang)` builds the list with
`new Intl.DisplayNames([lang], { type: "region", fallback: "none" })` (Node
ships full-icu since v14), falling back per-code to `FALLBACK_COUNTRIES`'
hardcoded Spanish names, then sorts with `localeCompare(…, lang)`. Results are
memoized per language in `localizedCountriesByLang`.

`fetchCountriesFromJustWatch(lang)` is **a misleading name kept for
compatibility** — it makes no network call at all; JustWatch has introspection
disabled so the country list is hardcoded. Served by `/api/countries?lang=xx`.

## Partial-translation warning (hi / te / ml / kn, added 2026-08-27)

`PARTIAL_TRANSLATION_LANGUAGES = new Set(["hi","te","ml","kn"])`, surfaced as a
`partialTranslation` boolean on each entry from `getSupportedLanguages()`.

Why: tested live against the real JustWatch API before adding them — mainstream
Hollywood titles plus "Pushpa" (Telugu) and "Dangal" (Bollywood) — and
`content(language: hi|te|ml|kn)` returns **byte-identical text to English** for
all of them. JustWatch accepts them as valid `Language` enum values (no GraphQL
error) but has no localized data. `ja`/`es` genuinely differ on the same titles,
so this is a specific data gap, not a general pattern.

Added anyway per explicit user decision, because this addon's **own** genre
names and catalog labels are real translations and addon-controlled,
independent of JustWatch. The UI warns instead of looking broken
(`#language-warning`, `updateLanguageWarning()`). No backend or URL-format
change was needed — `language` was already a free-form 2–3 letter code.

## Adding a language — checklist

1. Add its name to every entry in `GENRES` (`data/catalogMeta.js`).
2. Add it to `SORT_LABELS_I18N` (`domain/manifest.js`).
3. Add a full block to `UI_STRINGS` (`data/uiStrings.js`) — every key, non-empty,
   `{n}` preserved in `loadMore`.
4. Add it to `LANGUAGE_NAMES`.
5. If JustWatch has no content for it, add it to `PARTIAL_TRANSLATION_LANGUAGES`.
6. If it's RTL, add it to `RTL_UI_LANGUAGES`.
7. `npm test` — steps 1–3 are all enforced by the suite.
